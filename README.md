# Tampermonkey 用户脚本

个人 Tampermonkey 用户脚本集合，单个 `.user.js` 文件即产物，无构建步骤。

## 脚本列表

| 脚本 | 版本 | 说明 |
| --- | --- | --- |
| [浪潮云 CSS 工单自动转派](浪潮云CSS工单自动转派.user.js) | 1.5.0 | 勾选工单后按「云中心 → 负责人顺延链」配置自动分批完成批量转派，主备岗都停用时顺延或让你手动选人 |
| [浪潮云 CSS 工单详情转派](浪潮云CSS工单详情转派.user.js) | 1.3.0 | 详情页一键转派 + 查询列表页批量转派：可选认领/不认领、按账号搜人、填「请老师处理」并保存 |

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展
2. 打开对应脚本的 raw 地址，Tampermonkey 会弹出安装页：

   https://raw.githubusercontent.com/jiebukai/Tampermonkey/main/浪潮云CSS工单自动转派.user.js

   https://raw.githubusercontent.com/jiebukai/Tampermonkey/main/浪潮云CSS工单详情转派.user.js

也可以把 `.user.js` 文件直接拖进浏览器窗口安装。

## 浪潮云 CSS 工单自动转派

适用站点：`https://css.cloud.inspur.com/platform/*`（工单查询页面）。

### 使用

1. 在工单列表勾选一张或多张工单
2. 右下角出现「自动转派 (N)」按钮，点击
3. 核对确认面板（每个工单对应的处理人员、分成几批）
4. 点「确认执行」

脚本会依次完成：批量转派 → 确认弹窗 → 搜索并选中处理人员（技能组自动带出）→ 填写处理描述 → 保存。

如果某个云中心的负责人**全部被停用**，第 3 步之前会先弹出「选择处理人员」窗口，让你逐个云中心挑人；这次选择只对本次转派生效，不会改动配置。

### 负责人顺延规则

每个云中心有一串按优先级排好的负责人（「顺延链」），脚本从上往下找第一个**没被停用**的人：

```
权限回收负责人（主岗） → 权限回收负责人（备岗） → 一般变更二线主岗 → 一般变更二线备岗
```

- 表格里「权限回收负责人」两列填了内容的，就是权限已回收的云中心；这两列留空的（未回收），链条自动从「一般变更二线主岗」开始，跟以前「主岗 → 备岗」的效果一致
- 同一个人在多列重复出现会自动去重（例如北京大族云中心的回收主岗和一般变更主岗都是李新勇，不会来回跳）
- 一格写多个人（`李新勇、于雷`）时按书写顺序排进链里
- 整条链上的人都停用了，就弹窗让你手动选

### 云中心 / 负责人配置

负责人的来源有两个，按优先级：

1. **配置面板「数据源」导入的表**（保存在浏览器 `localStorage`，日常维护用这个）
2. 脚本顶部的**内置表**（导入表被清空时兜底）

内置表在脚本顶部，一行一个云中心：

```js
const BUILTIN_CENTERS = [
  { center: '北京大族云中心', primary: 'lixinyong', backup: 'huangchao01' },
  { center: '重庆云中心', primary: 'lishuangfeng', backup: 'yulei08' },
  // ...
];
```

- `center`：与工单列表「云中心」列**全等**匹配（避免「昆明云中心」误配「昆明呈贡云中心」）
- `primary`：主岗账号
- `backup`：该云中心的备岗账号

内置表是老的 3 列格式，导入 5 列新表后以导入表为准。

### 数据源（导入外部表格）

「⚙ 配置」→「数据源」，两种导入方式：

- **复制粘贴**：在 Excel 里选中表头 + 数据**整块**复制，直接 Ctrl+V 到文本框
- **选文件**：`.csv` / `.tsv` / `.txt`，UTF-8 或 Excel 中文版导出的 GBK 都能读

推荐对照的 5 列格式（跟日常维护的那张表完全一致，可以直接回灌）：

```csv
云中心,权限回收负责人（主岗）,权限回收负责人（备岗）,一般变更二线主岗,一般变更二线备岗
北京大族云中心,李新勇,黄超,李新勇,李双凤
济南云中心,,,黄超,吕本科、于雷
```

点「解析预览」检查结果，再选：

| 按钮 | 作用 |
| --- | --- |
| 替换全部 | 用导入的表**整个替换**当前表 |
| 合并到当前 | 同名云中心用新表覆盖，其余保留 |
| 导出当前表 | 导出成 5 列 CSV，可用 Excel 打开编辑后再导入 |
| 恢复内置 | 丢掉导入表，回到脚本内置的 56 个云中心 |

表格格式要求很宽松：

- 表头认 5 列：`云中心` / `权限回收负责人（主岗）` / `权限回收负责人（备岗）` / `一般变更二线主岗` / `一般变更二线备岗`；括号全角半角都行，多了「一般变更」「权限回收」等字样不会串列
- 老 3 列（`云中心 / 主岗 / 备岗`）照样能用；没有表头就按前三列的顺序读
- 人名可以直接写**中文姓名**（脚本自动换成账号），也可以直接写账号
- 一格可以写多人（`李新勇、于雷`），按书写顺序排优先级，重复的自动去重
- 认不出的姓名会**报错并拒绝应用**，不会带着错数据去转派
- 云中心重复出现时以最后一行为准，并给出提示

> 注意：导入是**全等匹配**，替换后如果新表里没有某个云中心，该云中心的工单会在执行前被拦下并列出。换一张口径不同的表（比如只列「未回收云中心」）时，建议用「合并到当前」而不是「替换全部」。

### 配置面板

右下角「⚙ 配置」打开，分三个标签页：

**人员开关**：列出所有负责人（显示姓名和账号），勾选 = 启用，取消勾选 = 停用。工单会沿顺延链跳过他/她，转给链上下一个启用的人；整条链都停用时会弹窗让你手动选。

**云中心指派**：逐个云中心手动指定处理人，**优先级高于表格里的顺延链**；每个云中心下面会显示它的整条顺延链（`李新勇 → 黄超 → 李双凤`），选「跟随规则」即恢复默认。顶部的搜索框可以按**云中心名**或**负责人姓名/账号**过滤（例如搜「济南」或「黄超」），命中的字会高亮，右侧显示「匹配 N / 总数」，按 Esc 清空。

**数据源**：导入 / 导出云中心负责人表（见上一节）。

这几个配置都保存在浏览器 `localStorage`，刷新后保留。若某个云中心在表格里一个负责人也没有，相关工单会在执行前被拦下并提示。

人员名单与姓名映射在脚本顶部的 `PEOPLE` 中维护：

```js
const PEOPLE = {
  lixinyong: '李新勇',
  lvbenke: '吕本科',
  huangchao01: '黄超',
  lishuangfeng: '李双凤',
  yulei08: '于雷',
  tanglei01: '唐磊',
};
```

### 行为说明

- 系统的批量转派一次只能指定一个处理人员，因此匹配到不同人员时会**自动按人员分组、逐批执行**；每批执行前脚本会重设勾选状态
- 任何一批失败会立即停止，提示已完成数量、失败人员和剩余批次
- 保存结果以抽屉关闭为准；失败时提示具体原因
- 确认面板里会标出每张工单是怎么定到人的：`（顺延第 N 位）`表示跳过了前面被停用的人，`（手动选）`表示来自手动选人弹窗
- 某个云中心在表格里一个负责人都没有的工单会被拦下并列出，不会静默跳过
- 手动选人弹窗里的候选人就是脚本顶部 `PEOPLE` 里的人（目前 6 个），要加人改 `PEOPLE` 即可

## 浪潮云 CSS 工单详情转派

适用站点：`https://css.cloud.inspur.com/platform/*`（工单详情页 + 工单查询列表页）。

### 使用（详情页：一键转派）

1. 打开一张工单的详情页，右下角会出现「转派」圆钮（在批量转派脚本的上方）
2. 点开面板，选择转给谁（尹航 / 马磊 / 解瑞杰 / 庾景铭 / 刘庆凯 / 郑鹏科），选择会记住
3. 面板第二行选「是否认领」：**认领**（默认）或 **不认领**，选择同样会记住
4. 点「一键转派给 XXX」，脚本会自动：按你的选择点「认领 / 不认领」→ 点「转派」→ 在弹窗里按账号搜索并选中处理人员 → 填「请老师处理」→ 点「保存」

### 使用（工单查询页：批量转派）

1. 在「工单查询」列表里勾选要转派的工单（一张或多张）
2. 打开右下角面板 —— 它会显示「列表页 · 已勾选 N 张」，多了这一行就不会认错模式
3. 选转给谁，点「批量转派给 XXX」，脚本会自动：点「批量转派」→ 点确认框的「确认」→ 在右侧抽屉里按账号搜索并选中处理人员（技能组由系统自动带出）→ 填「请老师处理」→ 点「保存」

同一张面板，按当前页面自动切换模式：详情页显示「一键转派给 XXX」和认领选项，列表页显示「批量转派给 XXX」并隐藏认领选项。

处理描述可以改成别的常用语，也会记住；出问题时点「诊断」可以把表单结构复制出来发我，用来调整选择器。

界面主题是蓝紫色，跟系统自带的蓝色按钮能区分开，不容易点错。

### 几个已经验证过的真实行为

- **必须先回答认领**：工单没选「认领此单」就直接点「转派」，系统会弹「请先选择是否认领工单」，弹窗根本不出现。脚本会按面板上的选择自动点「认领」或「不认领」再点转派。（认领后这一行会消失，脚本就跳过。）
- **批量转派多两步**：先点「批量转派」→ 弹「是否确认批量转派？」点「确认」→ 才出右侧抽屉表单。抽屉里的「处理技能组」是必填的，但选完处理人员后系统会自动带出，脚本不碰它。
- **不能转给自己**：下拉里当前登录人那一条是置灰的，点了不生效。脚本会直接报错说明，而不是卡住。
- **处理人员是服务端搜索**：下拉一次只显示前 10 条（全公司 1800 多人、182 页），必须输入账号才会去后台查。脚本输入账号后等结果收敛，没收敛会自动重搜，最多 3 次。
- **处理描述是富文本**：真正的输入区在 `<quill-editor>` 内层的 `.ql-container .ql-editor`，脚本只改这里，不会破坏工具栏。
- 成功判定：系统提示「转派成功」，或表单/抽屉自己关闭。
